# SimpleGrayClassification

> 参考来源：PyTorch 官方 [Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html) 系列教程，主要参考 [Quickstart](https://docs.pytorch.org/tutorials/beginner/basics/quickstart_tutorial.html) 的数据加载、网络训练、评估及参数保存流程。数据集来源：[NIST EMNIST](https://www.nist.gov/itl/products-and-services/emnist-dataset)。

这是一个基于 PyTorch 入门练习的 **EMNIST Balanced 47 类手写字符分类项目**。项目使用多层全连接网络，学习从数据加载到训练、评估和可视化的完整流程。目前属于基础实验，尚未完成性能优化或独立最终测试。

## 参考内容与项目扩展

教程原例使用 FashionMNIST 进行服装分类。本项目基于教程流程进行了以下整理和扩展：

| 部分 | 来源与改动 |
| --- | --- |
| Dataset、DataLoader、训练与评估循环 | 参考 PyTorch 入门教程的基本用法 |
| 数据集与模型 | 将 FashionMNIST 换为 EMNIST Balanced；网络调整为 `784 → 512 → 256 → 47` |
| 文件组织 | 将入口、模型、数据加载、训练、评估拆分为单独模块，并补充学习注释 |
| 指标记录 | 在教程流程上增加整轮损失、准确率统计和 CSV 保存，损失按样本数加权平均 |
| 可视化 | 增加数据样例、训练曲线、预测结果图及单张测试图片保存 |
| 独立预测入口 | 增加 `predict.py`，加载本地参数后生成样例预测结果 |

上述扩展是在学习过程中结合 AI 辅助完成的代码整理与功能实现，不将教程中的基础流程作为原创算法。

## 环境与依赖

需要 Python、PyTorch、torchvision 和 matplotlib。项目当前没有单独的依赖文件；依赖安装方式集中记录在这里。

```bash
python -m pip install torch torchvision matplotlib
```

有 NVIDIA GPU 时，可根据 [PyTorch 官方安装页面](https://pytorch.org/get-started/locally/) 选择适合本机的安装命令。没有 GPU 也可以使用 CPU。

开发环境曾使用 Python 3.12、PyTorch `2.14.0+cpu`、torchvision `0.29.0+cpu` 和 matplotlib `3.11.2` 进行小批次流程检查。这是已检查过的环境记录，并非对其他版本兼容性的保证，也不代表下方完整实验使用环境已被完整记录。代码使用了 `torch.accelerator` 和 torchvision transforms v2，过旧版本可能不支持。

## 数据集与预处理

- 使用 `datasets.EMNIST(..., split="balanced")`，共 47 类手写数字和字母，标签索引为 0～46。
- 图片为 28×28 单通道灰度图，训练集 112,800 张，官方测试集 18,800 张。
- `split="balanced"` 选择数据集版本；`train=True` / `False` 分别选择该版本的训练集和官方测试集。
- `v2.ToImage()` 将图片转为图像张量；`v2.ToDtype(torch.float32, scale=True)` 转成浮点数，并将像素缩放至 0～1。
- 当前未增加数据增强或额外的均值、标准差归一化。
- 数据固定保存到 `download_data.py` 旁的 `data/`，首次启动会通过 torchvision 自动下载，后续复用本地数据。首次运行需要网络连接和解压空间。

### 当前验证与最终测试的区别

**本文将每轮评估使用的数据称为“验证用评估集”。** 当前代码实际加载的仍是 EMNIST 官方测试集，函数名、终端输出、CSV 列名和曲线图例仍使用 `test`；它们在这里对应验证用途，不代表已经完成独立最终测试。

因为每轮都观察它的指标，并据此决定是否继续训练或调整超参数，这份数据已参与模型开发。它不会反向传播或更新参数，但已经不适合被视为完全未参与模型选择的最终测试集。

当前代码**尚未从训练集单独划出验证集，也未保留一份未参与调参的最终测试集**。仅修改文档或重命名曲线不能解决这一点。下一步应先确定训练、验证、最终测试的划分：使用训练集更新参数，使用验证集选择训练轮数和超参数，方案确定后才在未参与调参的数据上进行一次最终评估。如果官方测试集已用于调参，应如实披露；之后再划分数据也无法追溯地消除既有影响。

## 运行方法

在仓库根目录进入项目目录：

```bash
cd SimpleGrayClassification
python main.py
```

程序会加载数据、保存训练样例图，随后执行训练和每轮评估，记录曲线与指标，全部训练结束后保存 `model.pth` 及预测样例。当前 `main.py` 配置为 **20 轮**。

如果在 VS Code 中运行，先通过 `Python: Select Interpreter` 选择已安装依赖的环境，并确认打开的是 `main.py`。使用 Code Runner 时，应运行完整文件；终端命令末尾应是 `main.py`，而不是 `tempCodeRunnerFile.py`。

### 加载已有参数生成预测样例

```bash
python predict.py
```

运行前必须先完成一次 `python main.py`，生成本目录下的 `model.pth`。仓库通过 `.gitignore` 排除参数文件，当前没有提供可下载权重，因此克隆项目后不能直接假设该文件存在。

`predict.py` 创建相同网络，使用 `torch.load(..., map_location=device, weights_only=True)` 加载参数，再抽取 16 张评估集图片保存预测。它不会重新训练，也不会计算完整评估集指标。旧 FashionMNIST 的 10 类参数与当前 47 类输出层不兼容。

重新运行 `main.py` 会重新初始化网络，并覆盖同名参数、曲线和 CSV；它目前不是断点续训。需要保留不同实验时，请先备份旧结果。

## 模型与训练配置

```text
输入 [N, 1, 28, 28]
    → Flatten
    → Linear(784, 512) → ReLU
    → Linear(512, 256) → ReLU
    → Linear(256, 47)
    → 输出 [N, 47] logits
```

| 配置 | 当前值 |
| --- | --- |
| 模型 | 多层全连接网络（MLP），未使用卷积层 |
| 损失函数 | CrossEntropyLoss |
| 优化器 | SGD，未设置 momentum |
| 学习率 | 0.001 |
| 批次大小 | 64 |
| 训练轮数 | 20 |
| 训练数据顺序 | 每轮打乱 |
| 设备 | `main.py` 自动选择可用加速器，否则使用 CPU |

训练时直接将 logits 传给交叉熵损失；展示预测时才使用 softmax，再选择概率最大的类别。评估使用 `model.eval()` 和 `torch.no_grad()`，没有执行 `backward()` 或 `optimizer.step()`，因此不更新参数。

## 当前实验结果

以下数值来自本地 `outputs/history.csv` 中已有的 20 轮记录，并非本次编写 README 时重新训练所得。早先“10 轮约 46.7%”的描述已被更新记录替代：当前记录第 10 轮实际为 **46.20%**。

| 轮数 | 训练损失 | 训练准确率 | 验证用评估损失 | 验证用评估准确率 |
| --- | --- | --- | --- | --- |
| 1 | 3.8415 | 2.22% | 3.8299 | 3.39% |
| 10 | 2.4557 | 44.57% | 2.3329 | 46.20% |
| 20 | 1.4613 | 59.68% | 1.4598 | 59.61% |

这些评估数值对应 CSV 中的 `test_loss` 和 `test_accuracy`。训练指标是在参数不断更新的各个批次上累计的，评估指标是在整轮训练结束后的模型上计算的，因此两者并非完全相同条件下的比较。

第 20 轮较第 19 轮的评估准确率仍有上升，损失仍在下降，说明在这次记录的训练范围内尚未出现明显平台。训练和评估准确率接近，仅凭这些记录没有看到明显的训练集与评估集差距；这不能证明模型已经充分训练，也不能代替独立最终测试。

目前结果仍有较大改进空间。可以后续比较训练轮数、学习率、优化器及 CNN 等方案，但应在先确定验证协议后再进行比较。本项目不将当前结果描述为已优化完成的字符识别系统。

训练没有固定完整的随机种子，也没有保存每次实验的完整环境和配置快照，因此重新运行不保证得到完全相同的数值。

### 预测错例分析

下面是本地 `outputs/test_predictions.csv` 中的部分真实错例，索引指向当前官方测试集：

| 样例索引 | 真实字符 | 预测字符 | 预测概率 | 观察与待核查方向 |
| --- | --- | --- | --- | --- |
| 7756 | O | 0 | 48.48% | 字母 O 与数字 0 有形状相似性，需要结合具体笔迹检查混淆 |
| 6665 | B | 8 | 22.72% | B 与 8 都可能有两个封闭区域，是值得检查的形状混淆 |
| 15542 | g | O | 61.64% | 模型在错误预测上仍给出较高概率，最大概率不等于可靠程度 |
| 4116 | r | n | 60.27% | 可进一步检查笔画差异是否被模型区分，以及相同类别的更多样例 |

上述形状解释是根据标签对提出的分析方向，不是对图片成因的确定结论。应结合预测图或对应单张图片继续核查。固定抽取的 16 张样例仅用于观察，不能代表所有类别的错误分布；后续可增加混淆矩阵和各类别指标分析。

## 输出文件与可视化

所有结果位于项目的 `outputs/` 目录：

| 文件 | 内容 |
| --- | --- |
| `data_samples.png` | 16 张训练图片及真实字符 |
| `training_curves.png` | 每轮训练与验证用评估的损失、准确率曲线；代码图例仍标为 `test` |
| `history.csv` | 每轮指标，准确率以 0～1 保存 |
| `test_predictions.png` | 16 张评估图片，标注真实字符、预测字符和最大 softmax 概率 |

`save_samples()` 使用固定种子 `42` 选择样例，便于在同一数据集上比较不同模型；这只固定样例选择，不固定整个训练过程。预测正确用绿色标题，错误用红色标题。softmax 概率未经校准，不应直接解释为真实正确率。

图片通过 matplotlib 的 `Agg` 后端保存，不弹出绘图窗口。`outputs/` 已被 Git 忽略，因此以上记录和图片默认不会随仓库发布。本文结果表作为当前实验摘要保留；读者运行项目后可生成自己的输出。如需发布原始记录和图，应另外明确选择需要公开的实验产物。
